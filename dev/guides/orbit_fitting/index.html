Orbit Fitting

fit_orbit fits the relative orbit of a two-component system to interferometric observables.

using ROTIR

data = readoifits("betlyr_2007Jul03.oifits")[1, 1]

res = fit_orbit(data,
                UniformDisk(diameter = 0.57),                        # component 1
                EllipticalGaussian(fwhm = 0.90, ratio = 0.61, pa = 73.7);  # component 2
                elements = (P = 12.9414, e = 0.0, a = 0.865,
                            i = 93.5, Omega = 73.7, T0 = 2454283.043),
                flux_ratio = 0.81,
                method = :neldermead)

res.elements.a      # fitted semi-major axis, mas
res.chi2_red        # reduced χ²

Component 1 is at the origin and component 2 is displaced by the orbit:

cvis = (V₁ + f·V₂·exp(-2πi(u·Δα + v·Δδ))) / (1 + f)

with f the flux of component 2 relative to component 1.

Data

data is a single OIdata or a vector of them, one per epoch:

nights = [readoifits(f)[1, 1] for f in filter(endswith(".oifits"), readdir(dir, join=true))]
res = fit_orbit(nights, comp1, comp2; elements = (...))

All epochs are fitted with one set of orbital elements.

Default bounds: diameters and FWHM 0.01–20 mas, ratio 0.05–1, pa 0–180°, ld1 0–1, ld2 −0.5–1. The disk visibilities come from the OITOOLS model API (ud, ldlin, ldquad, ldpow), so ROTIR and OITOOLS use the same profiles.

Choosing what to fit

The parameters are the nine orbital elements a, i, Omega, omega, e, P, T0, dP, domega, the component parameters prefixed c1_ / c2_, and the flux ratio f. Each is free, fixed or tied:

howuse
freelisted in free, fitted within boundsconstrained by the data
fixednot listed; keeps its elements valueknown from elsewhere (an ephemeris)
tiedlisted in ties as an expressiondetermined by other parameters

P is required in elements; the others default to a = 1, i = 90, Omega = 0, omega = 90, e = 0, T0 = 0, dP = 0, domega = 0. Units: a in mas, angles in degrees, P and T0 in days, dP in days per day, domega in degrees per day.

res = fit_orbit(data, comp1, comp2;
                elements = (a = 0.9, i = 91.2, Omega = 73.5, P = 12.96, T0 = 2454283.0),
                free   = [:a, :i, :Omega, :T0, :f, :c1_diameter, :c2_fwhm],
                bounds = Dict(:a => (0.8, 1.0), :f => (0.1, 3.0)),
                ties   = Dict(:c2_pa => "-Omega"),
                method = :ultranest)

The default frees a, i, Omega, T0, f and every component parameter. Not free by default:

  • e and omega: at e = 0, omega is undefined.
  • P: usually known better from an eclipse or spectroscopic ephemeris. See Fitting the period.
  • dP: needs a long baseline for the phase drift to accumulate.
  • domega (apsidal motion): needs a baseline of years. Spica's periapsis advances about 2.6°/yr, so omega drifts about 21° across the 2007–2015 CHARA data.

Tied parameters

A tie computes one parameter from the others. Example: a disc in the orbital plane has its projected major axis along the line of nodes, so its position angle follows from Omega.

ties = Dict(:c2_pa => "-Omega")

Expressions are Julia code over the parameter names. A tie may reference another tie; ties are evaluated in dependency order, and a cycle is an error.

ties = Dict(:c2_pa    => "-Omega",
            :c2_ratio => "abs(cosd(i))")     # a flat disc's projected axis ratio

Ties are compiled once with RuntimeGeneratedFunctions; resolving them costs one allocation per likelihood evaluation.

A parameter listed as both free and tied is an error (orbit_fit_spec raises).

Position-angle conventions

EllipticalGaussian's pa is the angle of the minor axis (the one scaled by ratio < 1), measured from +RA toward +Dec. Omega is measured North through East. The major axis lies on the line of nodes when pa = -Omega. A wrong tie does not show in the χ²: the fit adjusts the other parameters around it.

To test a tie, fit the parameter freely once and compare. On β Lyrae the free position angle is 1.9° from the tied value, and the tie raises χ²/n from 3.154 to 3.189.

Degeneracies

The default bounds remove two exact degeneracies:

  • (Omega, T0) → (Omega + 180°, T0 + P/2) at e = 0: Omega is bounded to [0, 180) and T0 to one period centred on its starting value, so each solution appears once.
  • EllipticalGaussian pa: the profile is symmetric under a half turn, so pa is bounded to [0, 180).
The `Omega` bound assumes `e = 0`

Eccentricity breaks the (Omega, T0) degeneracy, and so do closure phases. For an eccentric orbit, widen the bound:

bounds = Dict(:Omega => (0.0, 360.0))

With the default, a published Omega = 309.9° folds to 129.9° and the fit finds the mirrored orbit. demos/spica_orbit_fit_tied.jl bounds Omega to 290–330°.

T0 and pa are periodic, but fit_orbit does not tell the sampler so; a mode at a bound is split in two. demos/betlyr/betlyr_orbit_fit_ultranest.jl calls UltraNest directly with wrapped_params for these two.

Fitters

fit_orbit(...; method = :neldermead)   # NLopt, point estimate (default)
fit_orbit(...; method = :ultranest)    # nested sampling, needs `using PythonCall`
fit_orbit(...; method = :nautilus)     # nested sampling, needs `using Nautilus`

The nested samplers also return posterior (nsamples × nfree), logz, logzerr, q16 and q84; the point estimate is the posterior median. maxeval = 20_000 bounds Nelder–Mead; min_num_live_points = 400 and use_stepsampler = true go to UltraNest. Plain region rejection (use_stepsampler = false) stalls on a sharply peaked posterior.

With a step sampler, UltraNest passes the likelihood one point at a time, so parallelism goes inside the likelihood (threaded = true).

Fitting the period

Free P as a consistency check:

res = fit_orbit(data, comp1, comp2;
                elements = (...),
                free   = [:a, :i, :Omega, :T0, :f, :P],
                bounds = Dict(:P => (12.9404, 12.9424)))

The data measure accumulated phase drift, n·δP/P over n orbits, so a short baseline gives a flat posterior on P. Keep the bound on P near the range the ephemeris allows over the baseline (including dP). The check shows whether the other elements move when P is free.

Performance

orbit_fit_data solves Kepler's equation once per distinct time, not per uv point. On β Lyr that is 50 times for 1613 uv points, and one likelihood over seven nights takes about 0.05 ms.

Evaluating without fitting

free = Symbol[] computes χ² at the given elements:

res = fit_orbit(data, comp1, comp2; elements = (...), free = Symbol[], verbose = false)
res.chi2, res.chi2_split      # total, and (V², T3amp, T3φ)

Tessellated components

model = :tessellated (ROTIR surfaces: Roche shapes, gravity darkening, irradiation) is not implemented and raises an error. For a tessellated binary, use create_binary_geometry and binary_chi2_f; see demos/spica_binary_roche.jl.

API

ROTIR.fit_orbit — Function
fit_orbit(data, comp1, comp2; elements, kwargs...) -> NamedTuple

Fit the relative orbit of a two-component system to interferometric data.

data is a single OIdata or a vector of them (one per epoch), straight from readoifits. comp1 and comp2 are OrbitComponents — component 1 sits at the origin, component 2 is displaced by the orbit.

Keywords

  • elements — NamedTuple of starting orbital elements. P is required; the rest default to a = 1, i = 90, Omega = 0, omega = 90, e = 0, T0 = 0, dP = 0.
  • flux_ratio = 1.0 — flux of component 2 relative to component 1.
  • free — parameter names to fit. Default: a, i, Omega, T0, f plus every component parameter. Component parameters are prefixed c1_ / c2_.
  • ties — parameters computed from the others instead of fitted, as Dict(:c2_pa => "-Omega"). See compile_ties. A parameter cannot be both free and tied.
  • bounds — Dict(:name => (lo, hi)) overriding individual boxes.
  • method — :neldermead (NLopt, fast, returns a point estimate) or :ultranest (nested sampling, returns a posterior and log Z).
  • model — :analytic (default) or :tessellated.
  • weights — observable weights, default OI_DEFAULT_WEIGHTS (V², T3amp, T3φ on).
  • maxeval, min_num_live_points, use_stepsampler — passed to the chosen fitter.

Returns

A NamedTuple with params (full vector), elements, chi2, chi2_split, chi2_red, spec, data, and — for :ultranest — posterior, logz, q16, q84.

Degeneracies worth knowing

At e = 0 the argument of periastron omega is undefined and is not fitted by default. The residual (Omega, T0) -> (Omega + 180°, T0 + P/2) degeneracy is broken by restricting Omega to [0, 180) while T0 spans one full period — together exactly one fundamental domain. An elliptical Gaussian's pa is likewise capped at 180°, since the profile is symmetric under a half turn.

P is not free by default: for most systems an eclipse or spectroscopic ephemeris pins it far better than a few nights of visibilities can, and freeing it mostly adds an unconstrained direction. Free it explicitly as a consistency check.

Example

data = readoifits("betlyr.oifits")[1, 1]
res = fit_orbit(data,
                UniformDisk(diameter = 0.57),
                EllipticalGaussian(fwhm = 0.90, ratio = 0.61, pa = 73.7);
                elements = (P = 12.9414, e = 0.0, a = 0.865,
                            i = 93.5, Omega = 73.7, T0 = 2454283.043),
                flux_ratio = 0.81,
                method = :neldermead)
res.elements.a, res.chi2_red

ROTIR.OrbitComponent — Type
OrbitComponent

A resolved (or unresolved) component of a binary, in the analytic visibility sense: it knows how to turn its own parameters into complex visibilities on a uv grid, and which of those parameters may be fitted.

Implementations: PointSource, UniformDisk, LimbDarkenedDisk, GaussianDisk, EllipticalGaussian.

source
ROTIR.PointSource — Type

Unresolved point source. No free parameters.

source
ROTIR.UniformDisk — Type

Uniform disk of angular diameter (mas).

source
ROTIR.LimbDarkenedDisk — Type

Limb-darkened disk of angular diameter (mas). law selects the profile and therefore how many coefficients are used: :linear (ld1), :quadratic (ld1, ld2), :power (ld1).

source
ROTIR.GaussianDisk — Type

Circular Gaussian of full width at half maximum fwhm (mas).

source
ROTIR.EllipticalGaussian — Type

Elliptical Gaussian: fwhm (mas) along the major axis, axis ratio in (0,1]. pa (degrees) is the angle of the minor axis, measured from +RA toward +Dec; the major axis is at position angle -pa (North through East).

pa is taken modulo 180: the profile is symmetric under a half turn, so a [0,360) range would hold two exact copies of every solution.

ROTIR.orbit_fit_data — Function
orbit_fit_data(data; T = Float64) -> OrbitFitData

Precompute the per-epoch quantities a fit needs. data is a single OIdata or a vector of them (one per night/epoch), as returned by readoifits.

Times are reduced to their distinct values: an OIFITS night typically has thousands of uv points but only tens of exposures, and the orbit only has to be solved once per exposure.

source
ROTIR.OrbitFitSpec — Type
OrbitFitSpec

The layout of a fit: which quantities exist, their starting values, their bounds, and whether each is free, fixed or tied. The parameter vector is

[a, i, Omega, omega, e, P, T0, dP, domega,
 <comp1 params>...,  <comp2 params>...,  f]

with component parameter names prefixed c1_ / c2_ so free = [:c2_pa] is unambiguous. The orbital block is ORBIT_ELEMENTS; index off length(ORBIT_ELEMENTS) rather than a literal, since it has grown once already (domega was appended for apsidal motion).

Every parameter is exactly one of:

  • free — listed in free, sampled within lo/hi;
  • fixed — absent from both, holding its starting value;
  • tied — listed in ties, computed from the others by compile_ties.

Build one with orbit_fit_spec, and turn a free-parameter vector into a full one with resolve_params — which is the only supported way to do so, because it is also what applies the ties.

source
ROTIR.orbit_fit_spec — Function
orbit_fit_spec(comp1, comp2; elements, flux_ratio = 1.0, free = nothing,
               bounds = Dict()) -> OrbitFitSpec

Assemble the parameter layout. elements is a NamedTuple of orbital elements (any of (:a, :i, :Omega, :omega, :e, :P, :T0, :dP, :domega); missing ones take sensible defaults, e = 0, omega = 90, dP = 0).

free is a vector of parameter names to fit; the default frees the four elements a two-component interferometric orbit actually constrains — a, i, Omega, T0 — plus the flux ratio and every component parameter. bounds overrides individual boxes, e.g. Dict(:a => (0.5, 1.5)).

ROTIR.resolve_params — Function
resolve_params(spec, p) -> θ

Build the full parameter vector from the free subset p: start from the fixed values, scatter the free ones, then apply the ties. This is the ONLY place a full parameter vector is constructed, which is the point — when the free-to-full mapping is written out at each call site instead, it is possible (and did happen) to build one that skips the ties, so a fit reports tied parameters still holding their starting values while quoting a χ² computed from the correct ones.

Follows the scheme OITOOLS uses in resolvers.jl: free values, fixed values and derived expressions resolved together in one pass rather than layered as separate copies.

source
ROTIR.compile_ties — Function
compile_ties(names, ties) -> OrbitTies

Compile ties (a Symbol => expression-string mapping) against the full parameter name list names. Errors on an unknown target, an unknown reference, or a circular definition.

source
ROTIR.apply_ties — Function
apply_ties(t::OrbitTies, θ) -> θ

Return a copy of θ with every tied entry replaced by its computed value. θ is returned unchanged (not copied) when there are no ties, so an untied fit pays nothing.

source
ROTIR.OrbitTies — Type
OrbitTies

Compiled tied-parameter rules for an OrbitFitSpec.

targets indexes the tied entries of the parameter vector, and fn(θ) returns their values as a tuple in that order. exprs keeps the original strings for display.

The type parameter F is load-bearing: with fn::Function (abstract) every call is a dynamic dispatch and the returned tuple is boxed, which costs ~3 allocations per likelihood evaluation. Concretely typed, resolving the ties allocates nothing beyond the parameter vector copy.
