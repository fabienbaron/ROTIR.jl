Chi-squared & imaging

Two forward-model paths

ROTIR computes complex visibilities from a surface map in two ways. They agree to rounding.

Matrix path

setup_oi! stores in each stellar_geometry a dense complex matrix polyft (Nuv × visible tessels) and the projected tessel areas polyflux. The visibilities are one matrix-vector product, cvis = polyft * xw / dot(polyflux, xw), with xw the visible map multiplied by vis_weights and ldmap; the gradient is the transposed product.

spheroid_chi2_fg, image_reconstruct_oi and binary_reconstruct_oi use this path and require setup_oi!. observables, chi2s and chi2_breakdown use it when polyft is set and the fused path otherwise.

Fused path

fused_spheroid_chi2_fg computes the visibilities without forming polyft, with the kernel selected by POLYFT_BACKEND (see Fused polygon Fourier transform); a second, adjoint pass gives the gradient. compute_adjoint_vertices! also gives the gradient with respect to the vertex positions, which the joint shape and map fit (shape_chi2_fg!, joint_reconstruct_oi) uses.

ROTIR.sobel_gradient_healpix — Function
sobel_gradient_healpix(n; T=Float32, power=2) -> (; Gx, Gy, D, owner, npix, area)

Gradient operators on the nested HEALPix sphere at nside = 2ⁿ, for "sobel" and "sobel2".

Gx, Gy (sparse npix × npix): (Gx*x)[i] and (Gy*x)[i] are the two components of ∇x at tessel i in an orthonormal basis of its tangent plane. Each row is the weighted least-squares gradient fitted to the tessel's 7 or 8 neighbours,

min_g  Σⱼ wᵢⱼ (g·tᵢⱼ − (xⱼ − xᵢ))²,      wᵢⱼ = |tᵢⱼ|^(−power)

with tᵢⱼ the tangent-plane projection of uⱼ − uᵢ (tessel centres). On a regular grid with power = 2 this is the 2-D Sobel stencil. Constants map to zero.

D (sparse, one row per directed neighbour pair, owner[r] the tessel of row r): rows √(2wₖ/tr Mᵢ)·(x_jₖ − xᵢ), so that the rows of tessel i give ‖D x‖² ≈ |∇x|ᵢ² for a smooth field. Unlike Gx, Gy, which give zero for a checkerboard, D vanishes only for a constant map; the regularisers use D.

area = 4π/npix is the solid angle of a tessel, so area·‖D x‖² approximates ∫|∇x|²dΩ independently of nside. A first derivative has a k² response, against k⁴ for the graph Laplacian of tv_neighbors_healpix.

ROTIR.laplace_beltrami_healpix — Function
laplace_beltrami_healpix(n; T = Float32) -> (; D, npix, area, nedges)

Cotangent Laplace–Beltrami operator on the nested HEALPix sphere at nside = 2ⁿ, for "laplace_beltrami". D is sparse nedges × npix, one row per edge of a triangulation of the tessel centres:

(D x)_e = √wₑ · (x_j − x_i),   wₑ = ½(cot αₑ + cot βₑ),   ‖D x‖² = Σₑ wₑ (x_j − x_i)²  ≈  ∫|∇x|² dΩ

with αₑ, βₑ the angles opposite edge e. ‖D x‖² is the Dirichlet energy of the piecewise linear interpolant of x (P1 finite-element stiffness matrix). It converges at O(h²): on the field z it is 1.6 %, 0.4 % and 0.1 % low at n = 2, 3, 4.

The tessel centres around each pixel corner (four, or three at the eight base-pixel vertices) form one face; quadrilaterals are split along their Delaunay diagonal, so every wₑ ≥ 0, and edges with wₑ = 0 are dropped. The triangulation has 2·npix − 4 triangles. The only null mode is the constant map. area = 4π/npix is returned for symmetry with sobel_gradient_healpix; ‖D x‖² needs no area factor.

ROTIR.spheroid_sobel_fg — Function
spheroid_sobel_fg(x, g, S; scale=1.0, verbose=false, ϵ=1e-8) -> f

Isotropic, edge-preserving total variation ("sobel") on the operator S = sobel_gradient_healpix(n):

f = scale · (4π/npix) · Σᵢ √(|∇x|ᵢ² + ϵ) / mean(x)   ≈   scale · ∫|∇x|dΩ / x̄

The square root is taken per tessel, so an edge costs in proportion to its height. ROTIR's "tv" is a different quantity, ‖Lx‖ (a global norm of the graph Laplacian, k⁴ response). Use "sobel" to keep edges such as spot boundaries, "sobel2" for a smooth map.

ϵ (in units of |∇x|² of the mean-normalised map) keeps the square root differentiable at ∇x = 0.

Gradient

With rᵢ = √(|∇x|ᵢ² + ϵ), m = mean(x), n = length(x) and A = 4π/npix,

∂f/∂xⱼ = scale·A·[ (Dᵀ(D x ./ r[owner]))ⱼ / m − (Σᵢrᵢ)/(n m²) ]

ROTIR.spheroid_sobel2_fg — Function
spheroid_sobel2_fg(x, g, S; scale=1.0, verbose=false, ϵ=1e-12) -> f

Quadratic gradient penalty ("sobel2") on the operator S = sobel_gradient_healpix(n):

f = scale · (4π/npix) · ‖D x‖² / mean(x)²   ≈   scale · ∫|∇x|²dΩ / x̄²

Invariant under x → c·x, as χ² is, and independent of nside for a smooth map, so a weight carries over between resolutions. Typical weights are O(1–10²).

Compared with "tv2" (‖Lx‖², L the graph Laplacian):

penalisesFourier responsescale-invariantnside-stable (smooth map)
"tv2"∇²xk⁴nono (×0.36 per doubling)
"sobel2"∇xk²yesyes

Gradient

With Q = ‖D x‖², m = mean(x), n = length(x) and A = 4π/npix,

∂f/∂xⱼ = scale·A·[ 2(Dᵀ D x)ⱼ / m² − 2Q/(n m³) ]

ROTIR.spheroid_laplace_beltrami_fg — Function
spheroid_laplace_beltrami_fg(x, g, S; scale=1.0, verbose=false, ϵ=1e-12) -> f

Dirichlet energy ("laplace_beltrami") of the cotangent Laplace–Beltrami operator S = laplace_beltrami_healpix(n), normalised like "sobel2":

f = scale · Σₑ wₑ (x_j − x_i)² / mean(x)²   ≈   scale · ∫|∇x|²dΩ / x̄²

Weights carry over from "sobel2" and between resolutions. Invariant under x → c·x; the only null mode is the constant map.

Gradient

With Q = ‖D x‖², m = mean(x), n = length(x): ∂f/∂xⱼ = scale·[ 2(Dᵀ D x)ⱼ / m² − 2Q/(n m³) ].

Binary imaging

Both surfaces of a binary, reconstructed at a fixed separation (from the orbit or a fitted offset). The unknown is the two maps concatenated, [x1; x2], split at stars1[1].npix.

stars2 = create_star_multiepochs(tess, p2, tepochs; secondary = true)
setup_oi!(data, stars1); setup_oi!(data, stars2)      # matrix path
shifts = [binary_phase_shift(data[i].uv, offs[i]...) for i in eachindex(data)]  # fixed
x0 = vcat(parametric_temperature_map(p1, stars1[1]),
          parametric_temperature_map(p2, stars2[1]; secondary = true))
x  = binary_reconstruct_oi(x0, data, stars1, stars2, shifts;
                           regularizers1 = regs1, regularizers2 = regs2, maxiter = 200)
map1, map2 = split_binary_map(x, stars1)

Each component has its own regulariser list. Structures in an entry (radflat_bins, orthold_direction) are built from that component's star, and a pixel subset in element 4 indexes that component's map, not the concatenated vector.

binary_cvis, binary_observables and binary_chi2_f take intensity_model, band and occultation (default false). binary_chi2_fg takes occultation only; binary_crit_allepochs_fg and binary_reconstruct_oi take neither, so a binary reconstruction uses the map as surface brightness and has no mutual occultation.

The GUI's Imaging tab reconstructs one component and refuses a model with a companion.

Saving a surface map

save_surface_map writes a map to FITS with its tessellation, the star_params it was computed with (integer fields stay Int), and optionally the epochs, so its χ² can be reproduced. See Saving a reconstruction.

ROTIR.save_surface_map — Function
save_surface_map(path, x, params; nside_exp, kwargs...) -> path

Write a surface map to FITS with what is needed to reproduce its χ².

x is the per-tessel map, params the star_params NamedTuple it was computed with, and nside_exp the HEALPix level as tessellation_healpix takes it (log₂ nside: 3 means nside 8, 768 tessels).

Keywords:

  • tessellation — :healpix (default) or :longlat.
  • tepochs, mjd — observation times: days since the first epoch, as create_star_multiepochs takes them, and absolute MJD. Written when given.
  • field — :temperature (default) or :intensity (limb darkening multiplied in).
  • secondary, chi2, ndata, comment — written to the primary header.

The file holds the map (primary HDU, tessellation in the header), a PARAMS table (name, value and Julia type of each numeric field of params) and, with times, an EPOCHS table.

To get the χ² back:

m = load_surface_map("map.fits")
tess  = tessellation_healpix(m.nside_exp)
stars = create_star_multiepochs(tess, m.params, m.tepochs; secondary = m.secondary)
setup_oi!(data, stars)
chi2_breakdown(m.x, stars, data)

Saving a model geometry

save_star_geometry writes the surface instead of the map: the tessellated mesh, the parameters it was built from, and for a binary the second component and its placement. The mesh is stored, so it is reproduced exactly, including a Roche component whose shape comes from a root solve at the instantaneous separation.

g = load_star_geometry("spica_primary.fits")
g.star                       # the mesh as saved
g.params                     # the parameters that built it
setup_oi!(data, [g.star])    # the Fourier setup is not stored
ROTIR.save_star_geometry — Function
save_star_geometry(path, star, params; nside_exp, kwargs...) -> path

Write a model's geometry to FITS: the mesh of star (a stellar_geometry) and the star_params NamedTuple params it was built from. No map is written.

nside_exp is the HEALPix level as tessellation_healpix takes it (log₂ nside).

Keywords:

  • tessellation — :healpix (default) or :longlat.
  • star2, params2 — a companion, given together. Its arrays go in HDUs with a 2 suffix.
  • place — :offset (default) or :orbit; offset — (West, North, toward observer) in mas, default (0, 0, 0).
