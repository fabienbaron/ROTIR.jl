Model Atmospheres, Stellar Physics & Spectra

Intensity providers, the derived stellar quantities they use, the surface velocity field and the velocity-resolved observables. See the guide Model atmospheres and limb darkening.

Derived stellar quantities

The mass is derived from (rpole, d, frac_escapevel, rotation_period); with it, each tessel has an absolute surface gravity.

ROTIR.derive_mass — Function
derive_mass(rpole_mas, d_pc, fev, period_days) -> M / M☉

Mass of a Roche rotator, in solar masses, from its polar radius (mas), distance (pc), fev = Ω/Ω_crit and rotation period (days):

Ω = 2π/P,    Ω_crit = √(8GM/27R_p³),    M = 27 R_p³ Ω² / (8 G fev²)

Uses the IAU nominal GM☉. Diverges as fev → 0.

ROTIR.derived_quantities — Function
derived_quantities(star_params) -> NamedTuple

Physical quantities implied by star_params: mass (M☉), rpole_rsun, req_rsun, logg_pole (cgs), veq and vsini (km/s), omega (rad/s). inclination defaults to 90° when absent. Returns nothing if has_physical_scale is false.

ROTIR.derived_summary_text — Function
derived_summary_text(star_params) -> String

One line with the mass, polar and equatorial radii, polar logg, and equatorial and projected velocities from derived_quantities, as shown in the GUI's Model tab. Empty unless surface_type == 2 and has_physical_scale holds.

source
ROTIR.has_physical_scale — Function
has_physical_scale(star_params) -> Bool

Whether star_params has d, rpole, frac_escapevel and rotation_period, which the physical quantities require.

source
ROTIR.logg_map — Function
logg_map(rpole_mas, d_pc, fev, period_days, sinθ, cosθ) -> Vector

Per-tessel log₁₀(g_eff) (cgs) of a rapid rotator, with the mass from derive_mass. sinθ, cosθ are the tessels' colatitudes. On a fast rotator it varies by 0.3–1.0 dex from pole to equator. Differentiable with Zygote.

source
ROTIR.logg_pole — Function
logg_pole(rpole_mas, d_pc, fev, period_days) -> log₁₀ g

Polar surface gravity, log₁₀ of cgs, with the mass from derive_mass.

source
ROTIR.equatorial_velocity — Function
equatorial_velocity(rpole_mas, d_pc, fev, period_days) -> km/s

Equatorial rotation velocity Ω R_eq, with R_eq = R_p·f(fev) from the Roche shape (R_eq reaches 1.5 R_p at fev = 1).

source
ROTIR.projected_veq — Function
projected_veq(rpole_mas, d_pc, fev, period_days, inclination_deg) -> km/s

Projected equatorial velocity v_eq sin i. The field vsini of derived_quantities holds the same value.

Temperature to intensity: choosing a source

The GUI's "Intensity from" setting; see From temperature to intensity.

ROTIR.INTENSITY_PARAMS — Constant
INTENSITY_PARAMS

The intensity-source settings, as ParamSpecs in display order: intensity_source (1 Planck, 2 ROTIR grid, 3 Kurucz pack, 4 Korg, 5 Rayleigh–Jeans; default 5), grid_choice, grid_path, the λ window in nm (grid_lambda_min/max, default 1500–1800), the Teff and log g axes (grid_teff_min/max, grid_logg_min/max) and grid_nodes (Korg only).

kind is :choice for the selectors, :path for grid_path and :setting for the numbers, which cannot be fitted.

source
ROTIR.INTENSITY_SOURCES — Constant

The intensity_source codes in INTENSITY_PARAMS.

source
ROTIR.SHIPPED_INTENSITY_GRIDS — Constant
SHIPPED_INTENSITY_GRIDS

The model-atmosphere grids that ship with ROTIR, as code => (file, label, ranges): the grid_choice codes of INTENSITY_PARAMS. intensity_grid_path resolves a code to its file; code 0 is a custom grid read from grid_path.

source
ROTIR.build_intensity_provider — Function
build_intensity_provider(cfg, path) -> IntensityProvider

Build the provider selected by cfg[:intensity_source] (codes in INTENSITY_PARAMS: 1 Planck, 2 grid file, 3 Kurucz pack, 4 Korg, 5 Rayleigh–Jeans).

cfg maps the numeric fields of INTENSITY_PARAMS to values (a Dict or a NamedTuple). path is grid_path, read only for a custom grid (grid_choice = 0). Raises on a bad configuration; validate_intensity_source checks one without building it.

Cost: 1 and 5 are immediate, 2 reads a FITS file, 3 parses the 67.5 MB Kurucz pack (downloaded on first use), 4 runs grid_nodes² Korg syntheses (seconds to minutes). Nothing is cached; save a built grid with save_intensity_grid and load it as source 2.

source
ROTIR.validate_intensity_source — Function
validate_intensity_source(ldtype, cfg, path) -> Vector{String}

Problems with an intensity-source configuration, one message each; empty if it can be built.

cfg maps the numeric settings to values (a Dict or a NamedTuple); path is grid_path. Only the settings the chosen source reads (intensity_params_used) are checked.

source
ROTIR.intensity_params_used — Function
intensity_params_used(source, cfg = nothing) -> Tuple{Symbol,...}

The settings that intensity source source reads; the GUI shows these. Planck and Rayleigh–Jeans read none. With cfg, grid_path is included only for a custom grid (grid_choice = 0).

source
ROTIR.intensity_spec — Function
intensity_spec(name) -> ParamSpec or nothing

The ParamSpec of an intensity setting by name, or nothing if name is not one (intensity_spec(:ld1) === nothing).

ROTIR.intensity_grid_path — Function
intensity_grid_path(cfg, path = "") -> String

The FITS file source 2 reads: a shipped grid resolved inside the package (grid_choice ≥ 1), or path for a custom one (grid_choice = 0). Empty when a shipped grid is missing from this installation.

ROTIR.intensity_lambda_range — Function
intensity_lambda_range(cfg) -> Tuple{Float64,Float64}

The (λmin, λmax) window in metres, from the nm values grid_lambda_min/grid_lambda_max (defaults 1500 and 1800 nm).

source
ROTIR.kurucz_pack_path — Function
kurucz_pack_path(; download = false) -> String

Path of the solar-metallicity ATLAS9 intensity pack ip00k2.pck19 (67.5 MB, Teff 3500–50000 K): ENV["ROTIR_KURUCZ_PACK"] if set, otherwise in intensity_cache_dir. With download = true a missing pack is downloaded from http://kurucz.harvard.edu/grids/gridp00/ip00k2.pck19; otherwise the path is returned whether or not the file exists.

ROTIR.intensity_cache_dir — Function
intensity_cache_dir() -> String

Per-user cache for downloaded intensity data: scratchspaces/ROTIR/intensity under the first Julia depot.

Intensity providers

ROTIR.IntensityProvider — Type
IntensityProvider

Source of the per-tessel emergent intensity I(Teff, logg, μ, λ).

Implement for a new backend:

functionmeaning
provider_intensity(p, Teff, logg, μ, λ)the intensity, elementwise over the vectors
provider_intensity_and_derivs(p, Teff, logg, μ, λ)it plus ∂I/∂Teff, ∂I/∂logg, ∂I/∂μ, ∂I/∂λ
owns_mu(p)true if I already contains limb darkening
needs_logg(p)true if logg is actually read (so a distance is required)
provider_support(p)(Teff, logg, λ) ranges, for refusing silent extrapolation

∂I/∂λ carries the gradient with respect to the velocity field: a velocity-resolved model evaluates each tessel at its rest-frame wavelength λ_obs/(1 + v_los/c).

source
ROTIR.RayleighJeansProvider — Type
RayleighJeansProvider()

Rayleigh–Jeans limit of PlanckProvider: I = λT/c₂, linear in temperature, with the same normalisation. Equal to intensity(T, :linear, …) up to a constant. owns_mu is false.

source
ROTIR.PlanckProvider — Type
PlanckProvider()

Non-dimensional Planck intensity, the same as intensity(T, :planck, …).

No μ or logg dependence (owns_mu and needs_logg are false); limb darkening comes from the ldtype law.

source
ROTIR.TabulatedProvider — Type
TabulatedProvider(grid; strict = false, name = "tabulated")

A precomputed (Teff, logg, μ, λ) intensity grid as an IntensityProvider.

Used for Kurucz ATLAS9, Korg/MARCS and any grid saved with save_intensity_grid. owns_mu and needs_logg are true, so it requires ldtype = 0 and a distance.

Out-of-range (Teff, logg, λ) are extrapolated linearly from the edge cell; strict = true raises an error instead.

source
ROTIR.RectGrid4 — Type
RectGrid4{T}

Values on a rectilinear (Teff, logg, μ, λ) grid, multilinearly interpolated.

Axes are strictly increasing and μ starts above 0; values is (nTeff, nlogg, nμ, nλ); λ is in metres. TabulatedProvider wraps one as an IntensityProvider.

source

owns_mu(provider) -> Bool

ROTIR.needs_logg — Function
needs_logg(provider) -> Bool

Whether the provider reads logg, in which case the model needs a distance d.

ROTIR.provider_support — Function
provider_support(provider) -> (Teff = (lo,hi), logg = (lo,hi), λ = (lo,hi))

The parameter ranges the provider covers.

ROTIR.check_provider_consistency — Function
check_provider_consistency(provider, star_params) -> Vector{String}

Problems with using provider with star_params; empty if none.

  • owns_mu(provider) with ldtype ≠ 0: limb darkening counted twice.
  • needs_logg(provider) without has_physical_scale: logg undefined.

ROTIR.provider_map — Function
provider_map(provider, Teff, logg, μ, λ) -> I

Zygote primitive for a provider's intensity. Differentiable in Teff, logg, μ and λ; provider itself is a constant.

source
ROTIR.analytic_test_grid — Function
analytic_test_grid(; kwargs...) -> (RectGrid4, f)

A RectGrid4 sampled from a smooth closed-form f(Teff, logg, μ, λ), together with f.

For testing the interpolation and its partials:

f = (Teff/6000)³ · 10^(−0.4(logg−4)) · (0.35 + 0.65μ^0.8) · (λ/2.2e-6)^(−1.7)

The interpolant equals f at the nodes; between nodes the error is second order in the cell size.

source
ROTIR.limb_mu_vec — Function
limb_mu_vec(nz) -> μ

max.(nz, 0): the μ an intensity provider is evaluated at, from the tessels' line-of-sight normal components nz (zero on the far side).

Backends

build_korg_grid and korg_provider need using Korg. The Kurucz readers need the intensity pack (kurucz_pack_path downloads it).

ROTIR.build_korg_grid — Function
build_korg_grid(; Teff, logg, μ, λ, kwargs...) -> RectGrid4

Synthesize a (Teff, logg, μ, λ) specific-intensity grid with Korg.jl.

Requires using Korg. MARCS covers Teff 2800–8000 K and logg −0.5 to 5.5; hotter stars need a Kurucz grid (read_kurucz_intensity) or a grid loaded with load_intensity_grid.

ROTIR.korg_provider — Function
korg_provider(; kwargs...) -> TabulatedProvider

source
ROTIR.read_kurucz_models — Function
read_kurucz_models(path; T = Float64, λrange = nothing, verbose = true) -> Vector{KuruczModel}

Parse every model in a Kurucz intensity pack.

λrange = (λmin, λmax) in metres restricts the wavelengths kept. A full pack is 1221 wavelengths × 17 angles × ~500 models; an H-band window keeps about 30 wavelengths.

I is absolute: the continuum column times the 16 packed intensity ratios.

source
ROTIR.read_kurucz_intensity — Function
read_kurucz_intensity(path; λrange, Teff = nothing, logg = nothing, T = Float64)
    -> RectGrid4

Read a Kurucz intensity pack into a RectGrid4 for TabulatedProvider.

  • λrange = (λmin, λmax) in metres, required.
  • Teff, logg: optional (lo, hi) restrictions of the axes. By default every (Teff, logg) in the pack with the full λ sampling is used.

The pack has no low-gravity models at high Teff and no high-gravity models at low Teff. Missing (Teff, logg) nodes are filled from the nearest logg at the same Teff, with a warning giving their number; restricting logg to the range the surface needs avoids this.

μ is returned ascending (0.01 … 1.0).

source
ROTIR.KuruczModel — Type
KuruczModel

One model atmosphere from a Kurucz intensity pack: Teff, logg, the wavelengths λ in metres, and I as (17, nλ) in erg/cm²/s/Hz/sr, μ in the file's descending order.

Velocity field

ROTIR.los_velocity — Function
los_velocity(star, star_params) -> Vector

los_velocity_from_proj for an existing stellar_geometry, reading inclination, position_angle, rotation_period, d and the optional vgamma/B_rot from star_params.

Raises an error if star_params has no distance d.

source
ROTIR.los_velocity_from_proj — Function
los_velocity_from_proj(pw, pn, incl_deg, pa_deg, period_days, d_pc;
                       vgamma = 0, B_rot = 0, cosθ = nothing) -> Vector

Line-of-sight velocity of each tessel centroid in km/s, positive receding, plus vgamma.

pw, pn are the (npix, 4) projected West/North vertex coordinates in mas (stellar_geometry.proj_west/.proj_north). Angles are in degrees, the period in days and d_pc in parsecs. Differentiable through the geometry's rules.

Differential rotation

B_rot ≠ 0 applies Ω(θ) = Ω₀ (1 − B_rot cos²θ) in colatitude θ: rotation_period is the equatorial period and B_rot > 0 makes the poles slower. It requires cosθ, the body-frame colatitude cosines (see los_velocity).

The velocity is evaluated at tessel centroids, which is exact for solid-body rotation and an approximation with shear. The surface shape and gravity darkening stay those of solid-body rotation, so B_rot is a kinematic perturbation only (a self-consistent model would need the Zorec et al. 2017 gravity darkening; see src/gravity_darkening.jl).

source
ROTIR.doppler_lambda — Function
doppler_lambda(λ₀, v_rad) -> λ

Observed wavelength(s) for a rest wavelength λ₀ and a receding-positive velocity in km/s:

λ = λ₀ (1 + v_rad/c)

Broadcasts over λ₀ and v_rad. First order in v/c; the second-order term is 3×10⁻⁷ at 300 km/s.

source
ROTIR.rest_lambda — Function
rest_lambda(λ_obs, v_rad) -> λ_rest

Rest-frame wavelength that a tessel with receding-positive velocity v_rad (km/s) contributes at the observed wavelength λ_obs:

λ_rest = λ_obs / (1 + v_rad/c)

The inverse of doppler_lambda. Broadcasts over λ_obs and v_rad.

source
ROTIR.velocity_field_summary — Function
velocity_field_summary(star, star_params) -> NamedTuple

(vmin, vmax, vspan, vsini_proj) of the visible hemisphere, in km/s.

vsini_proj is half the peak-to-peak line-of-sight velocity over visible tessels, which a rotational-broadening measurement constrains. projected_veq computes v_eq sin i from the parameters alone, so comparing the two checks the velocity field.

Velocity-resolved observables

ROTIR.surface_state — Function
surface_state(star, star_params; temperature_map = nothing) -> SurfaceState

Assemble the wavelength-independent per-tessel state of one epoch.

temperature_map defaults to parametric_temperature_map(star_params, star); pass a reconstructed or spotted map to use it instead.

Raises an error if star_params has no distance d. The weights include star.ldmap, so with a provider that contains limb darkening use ldtype = 0 (check_provider_consistency reports the mismatch).

source
ROTIR.channel_intensity — Function
channel_intensity(provider, state, λ_obs) -> Vector

Per-tessel intensity at observed wavelength λ_obs, each tessel evaluated at its rest wavelength rest_lambda(λ_obs, v_los).

source
ROTIR.spectral_cvis — Function
spectral_cvis(provider, state, star, data_channels; λ = nothing)
    -> (cvis, flux, λ)

Complex visibilities and total flux per wavelength channel, for one epoch.

data_channels is a vector of OIdata for one epoch at different wavelengths (a column of readoifits(...; polychromatic = true)); each carries its own uv. λ overrides the channel wavelengths.

cvis[c] is normalised (F/flux) as in fused_cvis. flux[c] equals line_profile's value.

source
ROTIR.line_profile — Function
line_profile(provider, state, λ_channels) -> Vector

Disk-integrated flux per channel: Σ I_i · w_i · dA_i over visible tessels, with w the visibility weights times ldmap and dA the projected areas. This is the normalisation used by the visibilities, without a Fourier transform (about 100× cheaper than spectral_cvis).

Returns flux in the provider's units; normalize_profile normalises it.

source
ROTIR.differential_observables — Function
differential_observables(cvis, λ, window) -> (dvisamp, dvisphi)

Differential visibility amplitude and phase across a line, relative to the continuum.

dvisamp[c] = |V_c| / |V_cont|
dvisphi[c] = arg(V_c) − arg(V_cont)      [degrees, wrapped to (−180, 180]]

with V_cont the mean complex visibility over the continuum channels (continuum_mask).

Each returned array is (nuv, nchannel). All channels must have the same number of uv points.

source
ROTIR.continuum_mask — Function
continuum_mask(λ, window) -> BitVector

true for channels outside window = (λ_lo, λ_hi): the continuum channels. Raises an error if fewer than two channels are outside.

source
ROTIR.normalize_profile — Function
normalize_profile(F, λ, window) -> Vector

F divided by its mean over the continuum channels (continuum_mask, as for differential_observables).

source
ROTIR.line_equivalent_width — Function
line_equivalent_width(F, λ, window) -> W

Equivalent width of the line in F, in the units of λ.

W = Σ (1 − F_c/F_cont) Δλ_c

over the channels inside window, with Δλ from the channel spacing. Positive for absorption.
